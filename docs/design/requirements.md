# 交给代码会话的完整实施提示词

更新：2026-09-30。适用工程：`项目根目录/`。这是当前唯一有效的需求与架构交接文档，替代早期同类方案。请在现有 0.3.0 上完成本轮升级，不另建一套应用。

## 1. 先理解我要的产品

这是一个简洁、素雅、适合长期使用的离线考研学习工作台。我希望它像一个安静的小世界：学习时有更清楚的雨滴和积水，偶尔掉落漂亮的小宝贝；资料是一排素白的立体书，每本书就是一门课程；收藏品可以摆进六个小水族箱。界面以场景和操作表达意思，不再堆口号、英文装饰标题、说明卡片和技术术语。

同时，它必须是一款可靠的本地应用。我的学习时间、积分、文件和收藏都在本机：不要重复复制文件、不要无限增长缓存与备份、不要升级丢数据、不要为了清理空间误删资料。代码也要收敛到一套清楚的实现，不能旧版新版并存、样式不断叠补丁。

本轮不是只做视觉稿：代码会话要完成正式业务、已有数据迁移、相关测试、视觉检查和新的 Windows 完整离线安装包。架构会话只编写本文件，没有在本轮修改业务代码或重新验证安装包。

### 用户已确定的要求

- 资料库改为素白、有立体感的书架；添加课程就出现一本书，书脊刻课程名，课程名自定义；点开书才能往课程内拖入 PDF 或文档。
- 雨滴更明显，正常前台学习时每秒约 3–4 滴。水层覆盖所有栏目内容，不能换页后被页面背景盖住。
- 偶尔落下小宝贝，按白、绿、蓝、紫、金、红六级区分。
- 掉落间隔按随机的 **10–30 分钟有效学习时间**，稀有度随机；其余具体概率由本方案确定。
- 导航新增“收藏品”；里面陈列六个有 3D 感的小水族箱，右下角有“仓库”入口。仓库与展示是两个不同页面/视图，从仓库选择宝贝放入展示缸。
- 仓库为格子布局，最多 50 格；可出售小宝贝获得积分。
- 可用学习时长可兑换积分；奖励商店改用积分购买，时间换积分的小面板放在奖励商店。
- 只维护一个最好的当前实现，删除真正废弃的代码、页面、重复样式和旧产物，重视本地存储占用。

### 已获用户认可的具体规则

架构会话提出后，用户确认“其他的都可以允许你”，只有掉落间隔被明确改为随机 10–30 分钟。因此以下作为本轮实施规则，不再重复询问：

- **60 秒可用时长 → 1 积分**，用户主动兑换，不自动把全部时间转积分；不足 60 秒保留。
- 仓库最多 50 件，一件占一格，同类不堆叠；六个展示位独立于仓库容量。因此最多持有 50 件仓储物品 + 6 件展示物品。
- 每个展示缸最多一件，六缸不强制对应六种稀有度，用户自由摆放。
- 仓库满时停止新掉落与掉落进度，不增加隐藏仓库、不自动出售、不积压奖励。
- 白/绿/蓝/紫/金/红的具体概率、售价、资产名单是下面的可调平衡配置；规则版本固定到每次产生的物品与交易，不因以后改配置改写历史。

## 3. 界面和交互，按这个意思实现

### 3.1 全局清爽化

导航保留：学习首页、学习记录、学习资料、收藏品、奖励商店、设置，图标加中文文字。删掉“YOUR COLLECTION”等装饰英文、重复理念说明、填充性口号和常驻技术解释。首页继续突出时间，保留开始/暂停/继续/结束、目标设置与必要金额标识；不要把主要时间缩成普通卡片。

删除杂文案不等于删除必要信息：按钮文字、输入标签、错误、未保存提示、余额单位、删除后果和离线能力仍清楚表达。帮助说明放进设置或按需展开，一处讲清，不在每页重复。空态只用一句，例如“添加第一门课程”。不要用表情符号充当正式收藏品资产。

延续已有考试目标功能：2027年12月，具体日未设置时不编造官方日期或倒计时；院校、分数、自设目标日可改。保留学习记录、备注和每日汇总。外观调整、导航和场景卸载不能改变计时。

### 3.2 资料库：素白书架

默认画面是暖白/素白书架、浅灰柔和阴影，有厚度的书脊和层板；低饱和、留白，避免花哨封面拼贴和密集表格。顶部仅“学习资料”、搜索和“添加课程”。

每门课程对应一个稳定 courseId 和一本书：

1. 添加课程只需课程名；书脊显示中文名，带浅浮雕/刻字质感，文字本身仍是可访问 DOM 文本。长标题合理换行/截断，悬停或焦点能看到全名。
2. 悬停书本轻微前移，点击打开课程。书本是可键盘操作的真实按钮，不是只有鼠标射线才能点击的装饰。
3. 课程内只显示课程名、返回书架、添加资料和文件列表/轻量卡片；没有文件时显示“将 PDF 或文档拖到这里”。整个课程内容区域可接收拖入，拖入时高亮，不常驻大块说明。
4. 文件支持打开、重命名显示标题、移到其他课程、移除。课程支持重命名和删除，书脊同步；删除课程默认保留资料到“未归档”，只有明确勾选才连同资料引用一起移除，并展示影响数量。
5. 首版支持 PDF、TXT、Markdown、DOC/DOCX、PPT/PPTX、XLS/XLSX、常见图片；文档是收藏管理，不承诺每种 Office 格式都有内置阅读器。PDF/图片/文本继续离线内置查看，其余使用本机关联程序；没有应用时给出准确提示。
6. 网页链接能力保留在课程内“添加资料”的次级菜单，不再抢占书架主视图；标注“网页”及需要联网，不把链接当已下载文件。
7. 书架初版每页/可见区最多渲染30本，超过时分页或虚拟化；搜索跨全部课程和文件，搜索结果明确所属课程，不能仅搜当前屏幕。

立体书架采用 CSS 3D transform、书脊/封面面片和柔和阴影即可满足本次“3D感觉”，不为每本书开 WebGL。六个收藏缸则用同一个 Three.js 场景表现真实玻璃空间。不要为书架引入第二套大型3D框架。

### 3.3 文件拖放：复用成熟库，保存仍走本地主进程

已检索 GitHub，选择 [react-dropzone](https://github.com/react-dropzone/react-dropzone)（MIT）作为外部文件拖入/选择区域的交互基础。它提供 React 文件拖放能力，不负责把文件可靠保存到本地；后者接现有 FileService。不引入 Uppy 的整套上传产品、服务器或云上传流程，也不使用仅用于列表排序的拖拽库冒充系统文件导入。

Electron 原生文件路径使用 preload 内的 `webUtils.getPathForFile(file)`；不要用已被替代的 `File.path`，不要把 File 当普通 JSON 跨 main IPC，也不要为了路径开启 nodeIntegration。preload 提供窄接口 `importDroppedFiles(files, courseId, operationId, datasetId)`，在 preload 从真实 File 解析路径并交 main；不把路径原样返给页面。main 检查 sender/frame/dataset、课程存在、普通文件、格式/大小、实际路径与符号链接策略。脚本构造且无磁盘来源的 File 应拒绝或走明确的文件选择入口。[Electron 官方说明](https://www.electronjs.org/docs/latest/api/web-utils)

在当前 Electron 沙箱与 contextBridge 下实测库返回的 File 是否保持可用；不可为了兼容直接复制整文件为 base64 穿过 IPC。导入按钮始终可用作补充，但真实 Windows 资源管理器多文件拖入必须验收，不得悄悄只交付“点击选择”。阻止整个应用默认的 drop 导航行为，只有课程页面接受导入。

单批默认最多100文件、单文件≤1GiB，超限给逐项原因；拒绝文件夹递归导入和可执行文件。同批部分有效文件可以导入，逐文件报告成功/重复/失败/取消，重试只处理未完成项。复制/哈希并发≤2，流式处理、有进度、可取消，不阻塞 main 和计时。

### 3.4 雨、水与前景层级

雨是视觉反馈，不是收入单位。每秒3–4滴不代表每秒赚3–4秒。正常可见学习状态以 250–333ms 随机间隔出滴，60秒应约180–240滴；增大雨滴高光、尺寸、落水圈对比，让浅色背景也能看见，但不能变成暴雨遮挡阅读。对象池有界，建议在途雨滴上限24、有效波纹上限24。暂停冻结，后台停渲染，回来不补播。

明确层级，而不是到处添加更大的 z-index：

| 层 | 用途 |
| --- | --- |
| 0 | 暖白全局底色 |
| 10 | 侧栏/页面/书架/收藏缸主体 |
| 20 | 全局透明水体、雨滴、涟漪、落宝动画，覆盖各页表面 |
| 30 | 需要清晰呈现的正文/时间/表单/操作控件 |
| 50+ | 弹窗、菜单、工具提示、拖放高亮和错误提示 |

把水层挂在 AppShell 根级固定容器/portal，覆盖侧栏、首页、记录、资料、收藏和商店；避免被局部 transform、isolation 或 overflow 裁剪。固定层级 tokens，不保留负 z-index 水层。水 canvas `pointer-events:none`，装饰不拦按钮、书本、拖放和滚动。必要控件提升到可读层，不代表整页铺不透明遮罩把水重新挡住。弹窗可读、可操作优先于装饰覆盖。

现有 renderer 清屏与 fragment 输出是不透明的：改为透明 renderer/clear alpha，并区分无水区透明、水区低透明度、雨滴和波纹；先检查 shader 是否全屏写 alpha=1。不能直接把整张照片/白底 shader 提到前景。WebGL 无法天然折射普通 DOM，不为“折射文字”每帧截图页面。用透明光影/水面表现前景积水，让文本维持清晰。

水位仍按本次有效学习/本次目标决定，到点溢流但收入继续；保持真实动态场景，不能用静态图替换。低动态减少运动但保留水位与材质；WebGL失败保留业务和明确兼容显示。

### 3.5 收藏品：六缸展示和独立仓库

收藏品首页为六个素白底座上的小玻璃水族箱，桌面3×2排布，窄窗口可2×3。每缸有可见侧面/厚度、水面或玻璃高光、柔和光影；放入物品后有轻微悬浮/转动，低动态时静止。六缸自由摆同一或不同稀有度，空缸也好看，不铺满操作文案。

右下角固定“仓库 n/50”入口；点开独立仓库视图/面板，清楚返回收藏品。仓库展示固定50个格子（桌面10×5，小屏自适应），物品缩略图配稀有度边线和可访问名称，空格保持安静。库存用轻量静态缩略图，禁止50个实时3D画布。

从仓库点击物品 → 详情展示名称、稀有度、售价 → “放入展示”选择六缸之一或“出售”。直接点击空缸可引导打开仓库选择，但操作源仍是已持有库存，不直接凭空生成物品。

- 移入空缸：warehouse → display，释放仓库1格。
- 替换已占用缸：同一事务中，把旧展示品放回被新物品腾出的那一格；满仓也能交换，不要求额外格子。
- 单独取回：display → warehouse，必须有空格；满仓不允许，给简短提示。
- 展示品不能被仓库的批量出售误售；必须先取回再售。
- 出售需确认，成功才移除物品并增积分；失败保留原物品。可以多选批售，但先核对全部ID/状态，整批原子提交，不能重复售一件。
- 不设隐式回收站保存另一份库存，不后台扩容，不让售出实例复活。

全应用最多两个 WebGL renderer：一个全局水层、一个收藏品展示场景；六缸共用 renderer、几何、环境和模型缓存，隐藏页面暂停/释放按实际需要处理。模型每种只加载一份，实例复用；旧模型/纹理及时 dispose。

## 4. 掉落：随机、持久化、与动效解耦

### 4.1 随机规则

每轮开始时由 main 使用 `crypto.randomInt(600000, 1800001)` 抽取10–30分钟目标有效毫秒，平均约20分钟。倒计时按有空仓位时、真正被计时服务认可并提交的学习增量推进，可跨多次学习会话累计。休息、睡眠、锁屏、关闭应用不推进；最小化/切页仍正常学习时可以推进。首次升级从0进度开始，不给所有历史累计时间追发宝贝。

随机的是下次间隔和稀有度；每次到点只掉一件，不再叠加一个“可能没掉”的判定，避免学习半小时仍没有任何惊喜。随机数只由 main 产生，renderer 不抽奖，不按雨滴数抽奖。

| 稀有度 | 白·普通 | 绿·清新 | 蓝·珍稀 | 紫·史诗 | 金·传说 | 红·典藏 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 整数权重/10000 | 5000 | 2800 | 1400 | 600 | 180 | 20 |
| 概率 | 50% | 28% | 14% | 6% | 1.8% | 0.2% |
| 出售积分/件 | 1 | 2 | 4 | 8 | 20 | 60 |

同稀有度中等概率选已启用物品；每级初版至少两种，共至少12种，且必须有资产，不能抽到占位ID。允许重复得到同种物品，实例ID不同，不堆叠。颜色之外同时标文字或徽记，白级在白底用灰边框。初版无保底/连抽/付费抽奖，也不将低概率描述成保证多久得到。

### 4.2 保存与满仓

`loot_state` 持久化当前轮 nextSeq、targetMs、progressMs、预先确定的 catalogId/rarity/sellPointsSnapshot、ruleVersion。生成一轮时就原子保存间隔和结果，UI不提前显示；重启、刷新、改变系统时间、切页不会重抽。新轮只在上一轮发放成功的同一事务里建立。测试允许注入 RNG，但正式 IPC 不得允许用户指定中奖结果或随意快进。

在学习检查点事务内处理掉落：提交学习收入 → 用本次可信增量推进 progress → 达阈值且有格子时创建唯一掉落事件和仓库实例 → 生成下一轮 → 一起提交。掉落事件 `UNIQUE(datasetId, sequence)`，实例 `UNIQUE(dropEventId)`。异常回滚重试不重复发物品；只允许数据库成功后播动画。普通5秒检查点导致发放延迟最多约一个正常检查点周期，不伪称严格即时；前台可在预计到点唤起同一个结算方法，不能另写收入路径。

满仓时进度冻结，不累计“欠发物品”。如果发放第50件，之后的有效学习仍正常记收入，但不继续推进下一轮。清空仓位前先结算到操作边界、按旧满仓状态丢弃该期间的掉落进度，再腾格；避免把满仓期间时间错误补回。已有未完成轮保留进度和结果，空出格后继续，不立即补一堆奖励。阈值刚到但由于并发操作无位时只保留这一轮待发状态，最多一件，不重抽。

掉落默认自动入仓，天空下落只是入仓后的视觉通知，无需用户点击抢取。前台显示短动画和不遮挡的一行名称；后台获得后下次展示简短汇总，不排长动画队列。动画播放与确认不决定所有权，崩溃后物品仍在仓库；提示使用最近已见事件水位，不能为每帧写数据库。

## 5. 积分与时间：两种资产、一个明确流向

保持累计学习 E 和可用时长 T 的区别。积分 P 是新的消费资产。不得新增“用时长直接买奖励”的并行入口。

```text
累计学习 E = 全部有效学习收入（毫秒，只因学习增加）
可用时长 T = E - 历史直接兑换消耗 - 新的时间换积分消耗
积分 P = 时间兑换收入 + 物品出售收入 - 积分商店支出
```

学习时预计T可以包含未保存量，显示要准确；所有交易由 main 先结算，再在事务里验证已保存余额。转换不扣累计学习，不改变本次水位或掉落进度，卖物品也不增加累计学习。积分不换回时长，不提供购买后再卖回赚差价的环。

商店顶部简洁显示积分余额，旁边“时间换积分”小面板：输入欲获得的整数积分q，显示将消耗 q×60秒、兑换后余额，点击确认。最大可换 floor(T/60000)，余量保留。价格与积分均为正安全整数，乘法、求和先校验溢出，零/负/NaN/小数拒绝。

转换事务必须同时写一条 time_conversion、一条负时间流水、一条正积分流水及幂等结果；任一步失败全回滚。出售事务同时核对仓库实例、标记售出、写正积分流水与售出收据。购买事务复用已有持久化兑换意图、商品version、名称/价格快照与幂等逻辑，改为只扣积分。重复点击/响应丢失/重启后确认同一意图不能重复交易；禁用按钮不是一致性保障。

核心用例：学习600秒，E=600秒、T=600秒、P=0；换10积分后E=600秒、T=0、P=10；购买2积分奖励后P=8；卖一件白级物品后P=9，E/T均不变。

## 6. SQLite 和文件：只保留一套本地存储

### 6.1 数据放哪里

沿用 `app.getPath('userData')` 和现有固定 appId，不在资料库另开一个 SQLite、不把数据库放安装目录、不放 renderer localStorage。数据库存课程、资料索引、时长/积分账本、物品实例、展示位置与设置；PDF/Office/图片等正文保存到受控附件目录，不塞为大型 SQLite BLOB，也不转 base64/JSON。

同一个附件对象可被多个课程资料引用。物品模型和缩略图属于随安装包发布的只读共享资产，数据库每个实例只存ID、稀有度、价格快照、状态与时间；掉落100件不能复制100份模型。所有字体/模型/贴图离线可用，不在首次启动自动下载。

### 6.2 内容去重和删除

复用 attachments/resources 思路，以 SHA-256 + sizeBytes 确认候选，同内容只落一份；对已有候选校验文件存在与内容完整性，异常文件不作可用副本。同课程重复内容默认提示“已在课程中”并跳过；不同课程可各有独立标题但共享附件。旧附件 original_name 移到资料引用级，不能共享后所有课程都显示第一次导入的名字。

导入流程：容量预检 → 流式复制到自管临时文件并同时哈希 → 验证类型/大小 → main 短写事务与内容唯一约束仲裁 → 已存在则复用，未存在则安全重命名入附件目录 → 写资料引用和每项幂等结果。复制过程中源文件变化，以最终复制内容校验为准，不用过期stat假设内容相同。写盘失败/取消清理临时文件，崩溃残留由启动清理处理。文件系统和SQLite不能天然同事务：必须保证“有引用的对象已完整存在”，允许短暂无引用孤儿，不能允许成功资料指向半文件。

从课程移除只删除引用；最后一个资料引用消失且没有备份/导入/预览任务占用时，才删受控副本。原始导入文件绝不能删。重命名、移动课程不复制字节。Windows文件占用导致删除失败入可重试队列，不假报已回收；预览关闭后再清理。

### 6.3 空间预算与回收

设置仅增加一个简洁“存储”页，显示实际用户资料、数据库、缓存、临时任务、自动安全备份/旧数据集占用和可回收量；包内资产与开发目录单独说明，不混成用户资料。数值通过按需异步扫描与缓存获取，不能每250ms递归遍历磁盘。

| 类别 | 规则 |
| --- | --- |
| 用户附件 | 默认5GiB软预算、80%提醒；超预算展示本批新增净占用并允许用户调整/明确继续，不能自动删资料。真实磁盘空间不足则阻止新增 |
| 数据库 | 核心记录保留；去掉逐帧/逐雨滴日志，检查点按下节收敛。以一年每天8小时、每天8会话的合成数据验证含索引目标≤100MiB，报告实际值，不能靠删历史达标 |
| 缩略图/可再生缓存 | 256MiB上限，LRU回收；用户文件不是缓存。收藏缩略图打包静态资源，无需反复生成 |
| 日志 | 最多5个×2MiB，轮转，正常模式不记录每个快照；错误保留最近信息，敏感完整文件路径不随意铺日志 |
| staging/partial | 成功、取消、失败在finally清理；失效检查令牌释放；启动清理无活动任务且超过24小时的自管残留，活跃任务不能被定时清理 |
| 自动安全副本 | 只在升级/迁移/恢复前创建，最多最近2份或1GiB，按较早触发的限制回收，但必须保留最近一个有效回滚点；单份超过预算须显示实际空间并让用户选目标/清理，不静默跳过安全副本 |
| 旧完整generation | 恢复验证完成后只保留最近一个可回滚数据集，默认7天；受恢复日志引用或未验证的新旧数据集不可自动删；统计单列其真实大小 |
| 用户手动导出备份 | 默认导出至用户选定位置，不在应用内另藏副本；永不自动删除应用外手动备份 |

磁盘预检计算本次峰值：净新增附件+临时复制/压缩输出+SQLite工作空间，至少留512MiB或本次估计10%的安全余量，取较大值；预检不是保证，写入中仍处理ENOSPC。大文件不做逐份全内存加载。PDF/Office通常已压缩，不为“省空间”长期另存原件、压缩件、解压件三份；不要自动改写/降质用户原文档。

SQLite用WAL和短事务，空闲时受控checkpoint，长读事务不可无限拖住WAL；需要缩库时检测可回收页和剩余空间，空闲维护并记录结果，不在每次退出/导入后全库VACUUM。清理过程检查绝对路径在预定自管根下，拒绝联接/符号链接越界。

### 6.4 限制检查点增长，仍保留约5秒恢复能力

不要单纯把检查点改成每小时来省空间。新模式每个会话只有一条学习收入行：活动中通过同事务单调提高其 amount_ms 与会话 credited_ms，结束后封存不改；日切片按 `(entryId, localDate, timezone)` 聚合更新。这是受约束的累计检查点，不是允许手改历史。支出、转换、积分交易仍是追加式不可变事件。

settle先从main可信累计量计算目标水位，仅写正差；同会话反复提交同一totalMs是无操作。金额、日期切片、掉落进度、会话水位和revision同事务。旧“每5秒一行”的收入在迁移时按会话合并、日切片按日期合并，前后总额/会话/日报逐项核对；旧支出收据完整保留。audit按新不变量更新，不能保留依赖旧逐行水位的断言却把它禁用。

command_results不记录只读查询和每次广播/检查点；经济操作保留紧凑可复原结果，关键交易保留唯一业务键，不按年龄盲删后让旧请求重放。无需通用事件总线、事件溯源框架或持久余额副本。快照需要缓存聚合时只作main内存可重建投影，成功事务后更新，重启/恢复重建。

### 6.5 备份完整但不重复搬运全库附件

保留SQLite backup API；禁止只复制正在用的sqlite主文件。先在短边界暂停并结算学习、生成数据库快照及附件manifest、固定引用集合；为备份任务固定这些不可变附件的读取占用。随后直接从已有附件流式写ZIP，不先把全体附件复制一份到staging。只需临时数据库/manifest和输出.partial，提供进度与取消。任务结束释放占用和清理临时目录；期间GC不能删除已固定附件。

恢复仍采用staging验证与完整generation切换：校验包路径/哈希/条目数/展开大小/数据库完整性/FK/时长与积分/库存与展示一致性，老格式先升级后再允许替换。以manifest计数/实际磁盘预算校验合理上限，不继续把所有合法备份固定卡在旧4GiB上限，也不能无限制解压。验证通过并用户确认替换后，保存安全回滚点，关闭库，写恢复日志和原子current.json。恢复失败保留完整旧数据，不混新数据库与旧附件。恢复换datasetId，旧页面请求失效。备份/恢复包含课程、积分、随机轮次、库存和展示位置，不能重新抽奖。

## 7. 数据契约、迁移与一致性

### 7.1 必要数据结构

以下是要达到的逻辑结构，名称可以适应工程，但不能再留第二套平行业务。所有金额为安全整数，SQLite约束、外键、唯一键与main校验共同保障。

| 数据 | 关键内容 |
| --- | --- |
| courses | id、name、sortOrder、createdAt；名称去首尾空格，空值拒绝 |
| resources | id、courseId、title、kind(file/url)、attachmentId/url、originalName、note；按kind互斥，FK，不存文件字节 |
| attachments | id、relativePath、sha256、sizeBytes、mime、status；sha256+size唯一；引用用查询确认，避免手写可漂移refCount |
| study_sessions / time_entries / study_day_slices | 沿用ID与记录，新学习收入每会话唯一，时间支出新增 conversion 关联；旧 redeem 只读历史；收入累计/日期与会话严格一致 |
| time_conversions | id、operationId UNIQUE、timeMs、points、rateVersion、createdAt |
| point_entries | id、amount 非零、kind(conversion/sale/purchase)、对应conversionId/saleId/redemptionId恰好一个、createdAt；每来源唯一，积分SUM为权威 |
| rewards | id、name、pricePoints>0、version、archivedAt；有效商品只有积分售价 |
| redemption_intents / redemptions | 复用持久报价/幂等；新意图仅points；收据用priceAmount+currency保留旧study_ms与新points区别 |
| collectible_catalog | 稳定ID、名称、rarity、model/thumbnail资产键、默认售价、assetVersion、启用状态；随包配置，升级upsert不能删除已拥有资产定义 |
| collectible_instances | id、catalogId、raritySnapshot、sellPointsSnapshot、state(warehouse/display/sold)、slotIndex、tankIndex、dropEventId UNIQUE、createdAt；仓库slot 0..49唯一，展示tank 0..5唯一，sold不占位 |
| loot_state | 单行轮次sequence、targetMs、progressMs、预抽catalog/rarity/sellPoints、ruleVersion；下一轮与本轮发放原子衔接 |
| loot_events / sales | 掉落sequence唯一、实例映射；售出收据与积分流水关联，重复售出不重复收入 |
| command_results / settings / migrations | 复用并规范；记录新规则版本/迁移checksum，禁止清空已有数据升级 |

状态约束：warehouse必须有slot且无tank；display必须有tank且无slot；sold两者皆空。一个物品只有一个位置，不能同时出现在仓库和展示。每槽至多一件；展示模型加载失败显示替代物和重试，不删除所有权。

新积分交易、卖物品、移位、转换、购买、课程写操作都走同一串行main命令队列。耗时文件I/O在事务外异步做，结束时再次检查datasetId/课程/配额等，禁止把新导入提交到刚被恢复替换的旧库。

### 7.2 从现有schema=1升级，不能抹掉旧学习成果

使用递增迁移和已有v1原始checksum，不改写已发布的初始SQL冒充新版本；修复Store只接受schema=1、备份manifest硬写schema=1的问题。迁移前读写锁/暂停/安全副本，失败回滚，未知未来版本拒绝写入。

1. 原resource_categories逐条迁为courses，尽量保持原ID与名称；原未分类资料进入“未归档”。文件、网页、备注、标题全部保留，旧分类表/旧页面/旧IPC在切换完成后移除，不能长期同时维护两套分类课程。
2. 旧附件按真实哈希和大小合并对象，资料引用改指保留对象；事务提交且核验后才清无引用副本，不删原文件。
3. 合并旧学习收入/日切片，验证总累计、可用余额、每会话和每日毫秒完全相等。金额不从显示的整数秒倒算。
4. 原可用时长原样保留，不自动兑换；新积分初始0，不按历史累计送积分或掉落。
5. 商品旧价格s秒迁为 `ceil(s/60)` 积分，保存一次性的迁移摘要供核对。这个规则会把非整分钟价格向上取整（最多不足60秒），升级提示一次且可立即编辑；旧收据保留原秒价对应的毫秒金额和currency=study_ms，不能伪装成当时花了积分。
6. 取消旧pending时间报价（无扣款），提示重新确认；新报价只用积分。旧已完成command_results及收据保持可查询，旧confirmed意图重放仍返回旧收据，不通过新积分流程再扣一次。
7. 新掉落从本轮升级后开始计有效时间，存好第一轮结果/间隔；新仓库、六展示位初始空。
8. 旧备份恢复走同一迁移器；恢复后原有效时间、积分（如有）、物品、随机轮次与资料保持一致。只有真正旧schema才按第4/7条初始化一次。

### 7.3 权威时间与故障规则继续保留

主进程以同进程单调纳秒差计时，内部毫秒、界面按秒显示；多次不足一秒收入可以累计。跨进程重启只恢复已存毫秒，绝不相减旧hrtime或把关机UTC差当学习。250ms采样只触发读数，约5秒checkpoint；暂停/结束/交易/关闭前立即结算。最小化继续；sleep/lock暂停，解锁后用户继续；无键鼠输入不能自动认定没学习。

现有>2秒可信采样空档冻结规则保留并实测，说明可能少记不确定尾段。写盘失败冻结计时/掉落/交易、保留待重试样本；事务未确认不能推进内存committed或播已获得动画。崩溃通常丢最近检查点尾段，约5秒不是无条件硬上限。恢复原会话不能重复发时间、积分或宝贝。

## 8. IPC和代码组织，少而清楚

保留 Electron 单实例锁、contextIsolation、sandbox、nodeIntegration=false、严格CSP和明确的具名业务接口。renderer不能任意SQL/文件路径/shell调用，preload不暴露完整ipcRenderer。响应保留结构化错误码，main是所有金额、库存、掉落、课程、文件权威。

在shared/contracts中给新增接口和返回值定义运行时schema与TS类型，清理本轮涉及的any，不为每个页面建立抽象仓储接口层。新接口可按实际风格命名：

- `listCourses/createCourse/renameCourse/deleteCourse/listCourseResources/moveResource`；导入按钮和拖入共用一条ImportService。
- `quoteTimeConversion/confirmTimeConversion/listPointTransactions`，商店沿用改造后的prepare/confirm redemption。
- `getCollection/getInventory/placeCollectible/returnCollectible/swapCollectibles/quoteSale/confirmSale`。
- `getStorageUsage/previewCleanup/runCleanup`，文件任务返回jobId，提供progress/cancel。

修改请求带datasetId、operationId及schema校验后的payload。货币转换/售出/购买用可持久化业务意图ID或来源唯一键；同操作ID改参数冲突，同意图多操作ID不得多次执行。文件每项也有幂等键，刷新/重试不复制一遍。

快照继续带processEpoch、snapshotSeq、dbRevision、时间状态；新增整数pointsBalance、inventoryCount、displayCount、lootBlockedByCapacity、最近掉落事件水位。不向renderer暴露下一轮预抽结果；下一次掉落可以保持惊喜，不显示精确预告。库存和目录仅在版本变化/打开时查询，不在每250ms快照里塞全部物品或扫描所有附件。

目标代码结构保持功能边界即可：

```text
main/
  time.ts                      唯一时间服务
  store.ts + migrations/       数据连接/事务/迁移协调
  library/                     课程、附件导入与引用清理
  economy/                     时间转换、积分、商店交易
  collection/                  随机掉落、库存、展示、出售
  storage/                     容量、备份/恢复、清理
  main.ts / preload.ts         生命周期与桥接
renderer/
  App.tsx                      壳、路由、全局状态，不再塞全部页面业务
  pages/                       首页、记录、书架/课程、收藏/仓库、商店、设置
  scene/                       唯一全局水层、收藏场景、共享资产生命周期
  components/                  真正复用的控件
shared/contracts.ts            唯一跨进程契约
```

不强制每个目录分成service/repository/factory三层，不造通用插件系统、事件总线、云同步框架和复杂游戏引擎。业务规则集中到少数明确函数，页面不自己算价格/抽稀有度。theme tokens统一布局，删除旧雨景/水缸分支与重复样式；保留真实迁移版本、历史交易币种和必要兼容代码，它们不是“冗杂”。

已核对可复用的官方来源：

这些是本轮查到的候选源，不是假称已经下载、挑好12个最终模型。代码会话需查看包内真实模型和缩略图，再挑至少12件风格统一、好看的轻量资产，建立实际文件清单。不要把整套330个模型全部塞进安装包，也不要把网站预览图当可再分发原件。

初版美术方向（名称为设计名，并不声称源包有同名文件）：白级小石/贝形摆件，绿级嫩芽/蘑菇，蓝级海蓝晶体/海洋摆件，紫级星月/魔法瓶，金级日轮/珍宝匣，红级赤晶/典藏摆件。选不到合适资产可换同档审美对象；稀有度由应用定义，不等于素材网站评级。每级至少两种不同轮廓，不能12件全是同一立方体换颜色。

模型尽量GLB、单件建议≤2MiB、贴图通常≤1024，新增收藏模型+缩略图总预算≤30MiB；平滑法线、适当金属/玻璃材质和统一光照比大纹理更重要。必要时只对选中模型进行压缩/减面，不引入运行时远程模型加载。优先CC0，其余逐件确认可在离线安装包再分发并保留署名；来源页、作者、许可证、原文件、hash、改动与应用catalogId写入现有资产来源清单。

本轮架构没有下载完整素材库，也没有伪造美术视觉验收。最终用户要看到真实可用资产，而不是一份“将来再找素材”的列表。

## 10. 删除旧版本与存储清理的执行边界

具体要求：先列清理清单与占用，检查文件引用、Git状态和运行进程，再清理。不要删 `.git`、真实用户userData、源资料、许可证、迁移、锁文件、仍有用的测试夹具。开发node_modules是构建依赖，不把删除它说成用户应用变小。

README、TEST_REPORT和本次实现报告更新到当前状态；旧版本报告的仍有效限制并入当前报告后，删除重复报告，不能把未完成的验收缺口一并删掉。联系目录仅保留本权威实施文档和当前实现报告；素材目录的来源/许可仍保留，因为它们不是产品方案副本。

## 11. 实施顺序与通过标准

按下面完整阶段连续推进。每阶段先完成相关测试与审查再继续，不把每个小步骤变成等待用户确认。重大产品含义问题才回报，普通实现错误自行修复。不创建/消息其他会话，不推送或发布。

1. **迁移和存储基础**：对现有schema=1夹具建立升级/回滚测试；整理版本迁移器；附件去重、空间统计、暂存清理、流式备份；收敛检查点增长。旧用户时间/资料/收据迁移一致后才继续。
2. **积分经济闭环**：时间换积分、商店积分价格/购买、历史币种区分、幂等和故障注入；UI能演示600秒→10积分→买2积分奖励剩8。
3. **课程书架与拖放**：真实课程创建/书脊/开书、资源管理、多文件系统拖入、离线打开、去重共享、搜索与课程迁移；清掉旧资料页面和分类API。
4. **水层修复与雨滴增强**：透明合成/跨页前景、3–4滴每秒、鼠标点击与拖放穿透；检查所有栏目、弹窗、低动态与后台恢复。
5. **随机掉落、50格仓库、六缸展示与出售**：先完成持久状态/事务，再接真实素材和3D；正常学习10–30分钟随机发一件，库存/展示/积分全闭环。不能只做静态水族箱。
6. **整合、精简与安装交付**：人工视觉检查、相关自动化/迁移/空间/故障测试、离线打包安装升级；新包可用后删除旧产物与失效实现，报告实际节省空间和剩余缺口。
